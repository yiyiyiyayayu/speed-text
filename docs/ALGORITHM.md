# 评分与推荐规则

## 原始样本

每节点采样 8 / 16 / 32 轮，默认间隔 700 ms，默认单轮 5 秒超时。独立 HTTP 连接经过节点发起 HTTPS GET。计时包含代理建立、目标 TLS 和小响应读取（最多 4 KiB）。只有 HTTP 200 / 204 且响应读取未报错才算成功；3xx、4xx、5xx、TLS 错误、超时均算失败。取消不作为失败计数，也不保存该节点未完成结果。

这是应用层往返观测，不是服务器的 ICMP RTT；失败率是请求失败率，不能称作真实网络丢包率。目标端点的封禁、宕机和限速也会影响结论。

失败样本用 -1 表示，不纳入延迟分位数。所有样本失败则评分 0。成功样本以线性插值计算中位数和 P95；抖动使用 `1.4826 × median(abs(x - median(x)))`，降低极少量异常值对抖动统计的干扰。异常尾延迟另外由 P95 扣分。

## 单次评分

令成功比例为 `p`，样本数为 `n`，中位数 `M`、P95 `T`、抖动 `J` 单位均为 ms。

```
z = 1.96
W = (p + z²/(2n) - z*sqrt(p*(1-p)/n + z²/(4n²))) / (1 + z²/n)
L = exp(-M / 250)
P = exp(-T / 450)
V = exp(-J / 80)
单次分 = 100 * p³ * (0.50*L + 0.30*P + 0.20*V) * (0.70 + 0.30*W)
```

`W` 是 95% Wilson 成功率置信下界，用于温和修正样本量。采样可能相关且时间窗口有限，因此不能把它解释为长期可用性的统计保证。尺度参数是首版的启发式工程默认值，并非机器学习预测。

下载 Mbps 不纳入评分，避免短时高吞吐掩盖频繁失败或卡顿。下载按读取到的正文位数 / 整个请求耗时计算，包括建连成本，属于保守的端到端吞吐指标。

## 历史平滑与可比性

同一订阅内使用节点配置（排除名称）SHA-256 前 128 位作为身份，节点重命名保持历史，凭据或配置改变则视为新节点。

只比较同一网络类型、同一测试 URL 的记录。当前评分权重 70%，最近 24 小时最多 12 次历史的评分均值权重 30%；历史均值包含当前记录。当前全失败或配置错误不能被旧高分拯救，直接得到 0 分。只使用 30 分钟内的最新结果作为推荐候选。

网络类型标签不含 SSID、运营商或 VPN 标识。不能自动保证历史来自同一条物理网络，换网络后应重测。不同并发设置、采样轮次、测试时段之间也可能有偏差。大量节点会分批测试，App 不声称所有节点同时观测。

## 推荐档位

在当前筛选列表里，候选节点需最新记录至少 6 个样本、成功数大于 0、失败率 ≤10%，且无配置错误。然后计算候选最高平滑分 `Smax` 和最低中位延迟 `Mmin`。满足全部条件进入推荐档：

```
平滑分 >= Smax - 8
P95 <= max(1.6*Mmin, Mmin + 60)
抖动 <= max(30, 0.35*自身中位延迟)
```

不符合时可以没有推荐节点。刚开始显示「初步推荐」。最近 24 小时内同类记录至少 3 次、样本至少 24 个且记录跨度至少 10 分钟后，显示「推荐」。这一标签表示已有更多观测，不保证未来表现。

建议先关闭下载运行一次，排除不可用节点；选择候选节点，在不同时间重复测试，再按需要单独开启下载。若要降低节点互相影响，设为单节点并行。
